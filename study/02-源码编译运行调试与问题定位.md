# 从0开始基于源代码编译运行调试，并添加日志定位问题

本文档介绍如何基于源代码进行开发调试，添加日志，定位问题。

## 环境准备

按照 `01-从0开始编译项目成npm包.md` 完成环境配置：
- Node.js 22+
- pnpm
- 已执行 `pnpm install` 安装依赖

## 开发模式运行

### 使用 Bun 运行 TypeScript（推荐，更快）

Bun 可以直接运行 TypeScript 文件，不需要预先编译：

```bash
# 运行 openclaw CLI
bun src/cli/openclaw.ts --help

# 运行特定命令，例如：
bun src/cli/openclaw.ts gateway status
```

### 使用 pnpm 运行开发版本

```bash
# 使用项目中配置的 pnpm dev
pnpm dev --help
```

## 完整编译后运行

```bash
# 编译
pnpm build

# 运行编译后的版本
node dist/cli/openclaw.js --help
```

## 添加日志定位问题

### 1. 使用内置日志工具

OpenClaw 有内置的日志工具，在代码中可以直接使用：

```typescript
// 导入日志
import { log } from '../src/logger'

// 添加不同级别的日志
log.debug('这是调试信息')  // 调试级别，只有开启debug才显示
log.info('这是普通信息')   // 普通信息
log.warn('这是警告信息')   // 警告
log.error('这是错误信息')  // 错误
```

### 2. 直接使用 console.log（快速调试）

在调试阶段可以直接使用 `console.log`：

```typescript
// 在需要调试的位置添加
console.log('>>> 函数参数:', paramName)
console.log('>>> 当前变量值:', variable)
```

### 3. 开启调试日志

运行命令时设置环境变量开启调试：

```bash
# Linux/macOS
DEBUG=* bun src/cli/openclaw.ts your-command

# 或者
NODE_DEBUG=* bun src/cli/openclaw.ts your-command
```

## VSCode 调试配置

如果你使用 VSCode，可以创建调试配置文件 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Debug OpenClaw CLI",
      "program": "${workspaceFolder}/src/cli/openclaw.ts",
      "preLaunchTask": null,
      "outFiles": ["${workspaceFolder}/dist/**/*.js"],
      "skipFiles": ["<node_internals>/**"],
      "args": ["--help"]
    }
  ]
}
```

然后你就可以：
1. 在代码行号左侧点击设置断点
2. 按 F5 启动调试
3. 逐步执行，查看变量值

## 问题定位步骤

### 步骤1：复现问题

首先确保你能稳定复现问题：

```bash
# 记录复现问题的完整命令
openclaw some-command --some-option
```

### 步骤2：增加日志输出

在可疑的代码位置添加日志输出，确认代码执行流程和变量值：

```typescript
console.log('>>> 进入函数 XYZ')
console.log('>>> 参数:', arguments)
console.log('>>> 变量 a 的值:', a)
```

### 步骤3：查看调用栈

如果遇到错误，可以打印错误栈：

```typescript
try {
  // 可疑代码
} catch (error) {
  console.error('错误详情:', error)
  console.error('错误栈:', (error as Error).stack)
  throw error
}
```

### 步骤4：二分法定位

通过注释代码 / 逐步缩小范围，找到问题出在哪一行哪一段。

## 编译问题排查

### 问题：构建时出现 "Cannot find module"

**解决方法：**
```bash
# 重新安装依赖
pnpm install
```

### 问题：修改代码后运行还是旧逻辑

**解决方法：**
```bash
# 如果是使用编译后版本，需要重新编译
pnpm build

# 如果直接运行 TypeScript（bun）则不需要重新编译
```

### 问题：类型错误，但代码逻辑没问题

**解决方法：**
- 查看类型错误信息，确认是否真的需要修复
- 某些第三方库可能类型不正确，可以使用 `// @ts-ignore` 临时跳过（不推荐，最好修复）

## 日志级别说明

| 级别 | 用途 | 默认显示 |
|------|------|----------|
| debug | 开发调试信息 | 否 |
| info | 普通信息 | 是 |
| warn | 警告信息 | 是 |
| error | 错误信息 | 是 |

## 高级调试技巧

### 1. 查看函数调用关系

可以使用 TypeScript 编辑器的"查找引用"功能，查看函数在哪里被调用。

### 2. git bisect 定位引入问题的提交

如果问题是最近引入的，可以使用 git bisect 快速定位：

```bash
git bisect start
git bisect bad HEAD       # 当前版本有问题
git bisect good v2026.2.0 # 上个已知正常的版本
# 然后根据提示逐步检查，直到找到问题提交
```

### 3. 对比已知正确版本

```bash
# 对比差异
git diff main...your-branch -- src/path/to/file.ts
```

## 总结

调试问题的一般流程：
1. 复现问题 → 2. 添加日志 → 3. 定位代码位置 → 4. 分析原因 → 5. 修复验证

善用 `console.log` 和断点调试，可以快速定位绝大多数问题。
